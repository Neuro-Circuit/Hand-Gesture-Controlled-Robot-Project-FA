## نمای کلی

**Hand Gesture Control** یک سیستم بینایی ماشینِ بی‌درنگ و قابل توسعه است که حرکات دست را از طریق وب‌کم تشخیص داده و آن‌ها را به دستورات کنترلی مستندشده تبدیل می‌کند.

این پروژه بر پایه یک **معماری پایتونی مبتنی بر افزونه (Plugin-based)** ساخته شده و از API مدرن **MediaPipe Tasks Hand Landmarker** استفاده می‌کند. سیستم می‌تواند به‌صورت مستقل با یک یا دو دست کار کند، دستورات زنده را از طریق WebSocket در اختیار قرار دهد، جریان تصویر دوربین را در مرورگر نمایش دهد، دستورات را به‌صورت JSON Lines ثبت کند و دستورات عددی حرکت را از طریق UDP به یک ESP32 برای کنترل یک ربات چهارچرخ با سیستم حرکتی دیفرانسیلی ارسال کند.

## ویژگی‌های کلیدی

* **ردگیری مستقل دو دست:** دست چپ و راست تاریخچه و وضعیت تشخیص جداگانه‌ای دارند، بنابراین حرکات دست‌ها با یکدیگر تداخل نمی‌کنند.
* **هندسه دو دست:** زمانی که هر دو دست قابل مشاهده باشند، سیستم یک چارچوب هندسی بین آن‌ها ایجاد می‌کند. اندازه، مرکز و زاویه این چارچوب به‌عنوان یک دستور مستندشده در اختیار قرار می‌گیرد و می‌تواند برای تعاملاتی مانند کنترل بزرگ‌نمایی استفاده شود.
* **داشبورد زنده در مرورگر:** آدرس `http://127.0.0.1:8000` جریان تصویر دوربین، نقاط دست، خطوط اتصال و اطلاعات زنده دستورات را نمایش می‌دهد.
* **API بی‌درنگ WebSocket:** آدرس `ws://127.0.0.1:8765` به برنامه‌های رباتیک، اسکریپت‌های Python، Unity، Node.js یا سایر نرم‌افزارها اجازه می‌دهد دستورات JSON را دریافت کنند.
* **کدهای عددی پایدار برای دستورات:** هر دستور دارای یک `code` عددی ثابت است که یکپارچه‌سازی با سیستم‌های نهفته را ساده می‌کند.
* **پردازش مناسب برای CPU:** پروژه بر پایه ردیابی دست MediaPipe طراحی شده و به GPU نیاز ندارد.
* **جریان کامل Hand Rig:** هر فریم می‌تواند ۲۱ نقطه دست، اطلاعات مفاصل، وضعیت انگشتان و زوایای خم‌شدن را در قالب یک دستور استاندارد ارائه کند.
* **قابلیت توسعه مبتنی بر افزونه:** حرکات جدید تک‌دستی یا دودستی را می‌توان بدون تغییر موتور اصلی تشخیص، به‌صورت کلاس‌های جدید اضافه کرد.
* **مستندسازی خودکار:** رجیستری دستورات می‌تواند هم مستندات Markdown قابل خواندن برای انسان و هم JSON Schema قابل استفاده برای ماشین تولید کند.
* **پیکربندی YAML:** آستانه‌ها، نرخ‌ها، خروجی‌های فعال، تنظیمات دوربین و سایر رفتارهای زمان اجرا را می‌توان بدون تغییر کد منبع Python پیکربندی کرد.
* **یکپارچه‌سازی با ربات:** یک UDP Sink اختصاصی، دستورات عددی پایدار را از طریق Wi-Fi به ESP32 ارسال می‌کند.

## چرا MediaPipe؟

این پروژه از API مدرن **MediaPipe Tasks Hand Landmarker** استفاده می‌کند، زیرا برای تشخیص بی‌درنگ نقاط دست طراحی شده و می‌تواند به‌صورت کارآمد روی سخت‌افزارهای مبتنی بر CPU اجرا شود.

پروژه عمداً از API جدید Tasks استفاده می‌کند:

```python
mediapipe.tasks.python.vision.HandLandmarker
```

و نه API قدیمی و منسوخ‌شده:

```python
mp.solutions.hands
```

یک فایل مدل کوچک با نام `hand_landmarker.task` موردنیاز است. پروژه می‌تواند این فایل را در اولین اجرا دانلود کرده و در پوشه `models/` ذخیره و کش کند. بنابراین فقط برای دانلود خودکار اولیه به اینترنت نیاز است.

اگر دانلود خودکار با مشکل مواجه شد، مدل را می‌توان به‌صورت دستی دانلود کرده و در مسیر زیر قرار داد:

```text
models/hand_landmarker.task
```

# سیستم کد عددی دستورات

هر دستور دارای موارد زیر است:

۱. یک شناسه قابل خواندن برای انسان: `command_id`
۲. یک عدد صحیح ثابت: `code`
۳. برچسب‌ها و فراداده
۴. پارامترهای اختیاری
۵. اطلاعات اطمینان و زمان ثبت

کد عددی هنگام ثبت دستور به‌صورت صریح تعیین می‌شود. این کد **به‌صورت خودکار تولید نمی‌شود**؛ بنابراین پروتکل پایدار و قابل کنترل باقی می‌ماند.

نمونه:

```
     کد     معنی
```

---

```
      `0` حرکت انگشت اشاره به پایین
      `1` حرکت انگشت اشاره به بالا
      `2` حرکت انگشت اشاره به چپ
      `3` حرکت انگشت اشاره به راست
      `4` مشت
`6`--`11` حرکت کلی دست
     `19` چارچوب هندسی دو دست
```

به‌صورت پیش‌فرض، خروجی کنسول را می‌توان طوری تنظیم کرد که فقط کد عددی را چاپ کند:

```text
0
0
7
4
```

در `config/gestures.yaml`:

```yaml
output:
  console:
    mode: numeric   # پیش‌فرض: فقط عدد چاپ شود
    # mode: full    # اطلاعات کامل برای دیباگ
```

ثبت JSON و خروجی WebSocket نیز همین مقدار عددی را در فیلد `code` شامل می‌شوند.

# افزودن یک حرکت جدید

معماری به شکلی طراحی شده است که یک حرکت جدید تک‌دستی بدون تغییر موتور اصلی قابل اضافه‌شدن باشد.

نمونه:

```python
from core.gesture_base import GestureDetector
from core.command import Command, CommandRegistry
from core.landmarks import finger_states

CommandRegistry.register(
    "hand.peace_sign",
    20,
    "علامت صلح",
    "علامت صلح",
    "gesture",
    "علامت صلح تشخیص داده شد",
    {}
)

class PeaceSignDetector(GestureDetector):
    def update(self, points, frame_shape, timestamp, hand_label):
        states = finger_states(points)

        if (
            states["index"]
            and states["middle"]
            and not states["ring"]
            and not states["pinky"]
        ):
            return [
                CommandRegistry.make_command(
                    "hand.peace_sign",
                    hand=hand_label
                )
            ]

        return []
```

سپس تشخیص‌دهنده را در `build_detectors` در `main.py` اضافه کنید.

### نکته مهم

کد هر فرمان باید یکتا باشد. اگر یک کد تکراری ثبت شود، `CommandRegistry.register` بارگذاری برنامه را با یک خطای واضح متوقف می‌کند و اجازه نمی‌دهد یک تداخل به‌صورت بی‌صدا رخ دهد.

برای حرکات دودستی، به‌جای `GestureDetector` از `TwoHandDetector` ارث‌بری کنید و `left_points` و `right_points` را به‌صورت هم‌زمان پردازش کنید.

# یکپارچه‌سازی بی‌درنگ WebSocket

با فعال‌کردن:

```yaml
output:
  websocket:
    enabled: true
```

یک برنامه دیگر می‌تواند به آدرس زیر متصل شود:

```text
ws://127.0.0.1:8765
```

نمونه کلاینت Python:

```python
import asyncio
import json
import websockets

async def listen():
    async with websockets.connect("ws://127.0.0.1:8765") as ws:
        async for message in ws:
            cmd = json.loads(message)

            print(cmd["command_id"], cmd["params"])

            # فرمان را در برنامه خود به یک عمل واقعی تبدیل کنید.
            # نمونه:
            # if cmd["command_id"] == "hand.move.right":
            #     robot.move_right(cmd["params"]["speed"])

asyncio.run(listen())
```

این رابط باعث می‌شود موتور تشخیص برای نرم‌افزارهای رباتیک، بازی‌ها، شبیه‌سازی‌ها، سیستم‌های تعاملی، ریگ‌های کاراکتر و سایر برنامه‌ها قابل استفاده باشد.

# یکپارچه‌سازی کنترل ربات

این پروژه می‌تواند یک ربات **چهارچرخ با سیستم حرکتی دیفرانسیلی (Differential Drive)** را با استفاده از تجهیزات زیر کنترل کند:

* ESP32-WROOM-32U
* درایور موتور L298N
* ۴ موتور DC
* دو باتری لیتیوم‌یون 3.7V مدل 18650 به‌صورت سری
* مبدل کاهنده DC-DC مدل LM2596
* شاسی ربات چهارچرخ
* بردبورد کوچک

## تجهیزات سخت‌افزاری موردنیاز

قطعه              نیازمندی

---

کنترلر            ESP32-WROOM-32U، مدل ۳۲ پایه
درایور موتور      L298N
موتورها           ۴ × موتور DC
منبع تغذیه        ۲ × باتری لیتیوم‌یون 3.7V مدل 18650 به‌صورت سری
مبدل DC-DC         LM2596
شاسی              شاسی ربات چهارچرخ
برد نمونه‌سازی    بردبورد کوچک

> **نکته تغذیه:** مستندات اصلی پروژه یک ریل تنظیم‌شده 5V را برای سیستم ربات مشخص می‌کند و توصیه می‌کند پیش از اتصال تجهیزات الکترونیکی، خروجی LM2596 را با استفاده از مولتی‌متر دقیقاً روی 5V تنظیم کنید.

## ENA / ENB

در پیکربندی مستندشده، پایه‌های `ENA` و `ENB` از طریق پیکربندی تغذیه/جامپر درایور فعال باقی می‌مانند تا موتورها با حداکثر سرعت کار کنند.

کد فعلی کنترل ربات، کنترل سرعت متغیر موتور را از طریق PWM پیاده‌سازی نمی‌کند.

# منبع تغذیه --- LM2596

معماری تغذیه مستندشده به شکل زیر است:

```text
۲ × باتری 3.7V 18650 (سری)
                │
                ▼
        ┌──────────────┐
        │    LM2596    │
        │ مبدل کاهنده  │
        └──────┬───────┘
               │ 5V تنظیم‌شده
        ┌──────┴─────────────┐
        ▼                    ▼
      ESP32                 L298N
                             │
                             ▼
                           موتورها
```

### قوانین سیم‌کشی

* `IN+` و `IN-` ماژول LM2596 را به دو سر پک باتری متصل کنید.
* پیش از اتصال تجهیزات الکترونیکی، با استفاده از مولتی‌متر و پتانسیومتر ماژول، `OUT+` و `OUT-` را دقیقاً روی **5V** تنظیم کنید.
* خروجی تنظیم‌شده 5V را به `VIN` و `GND` مربوط به ESP32 متصل کنید.
* ورودی تغذیه منطقی مناسب L298N را به منبع تغذیه تنظیم‌شده متصل کنید.
* موتورها برق خود را از طریق L298N دریافت می‌کنند.
* ESP32، L298N، سیستم باتری و زمین توان موتورها باید `GND` مشترک داشته باشند.
* هنگام برنامه‌ریزی، ESP32 را می‌توان از طریق Micro-USB نیز تغذیه کرد.

# گیرنده UDP در ESP32

ESP32 روی پورت UDP زیر گوش می‌دهد:

```text
4210
```

محتوای مورد انتظار بسته باید یک کد عددی فرمان باشد، برای مثال:

```text
10
```

ESP32 کد دریافتی را به حرکت ربات تبدیل می‌کند.

## نگاشت فرمان‌های ربات

کد UDP             حرکت ربات

---

`9`، `10`، `11`     حرکت به جلو
`15`، `16`          حرکت به عقب
`6`                 توقف
`0`، `1`، `2`، `3`   چپ
`12`، `13`، `14`    راست

پیاده‌سازی ESP32 همچنین از موارد زیر پشتیبانی می‌کند:

* تنظیم IP ثابت
* غیرفعال‌کردن خواب Wi-Fi با استفاده از `WiFi.setSleep(false)`
* اتصال مجدد خودکار به Wi-Fi
* دریافت UDP روی پورت `4210`
* نگاشت فرمان به موتور از طریق L298N

### نمونه پیکربندی شبکه ESP32

```cpp
IPAddress local_IP(192, 168, 1, 150);
IPAddress gateway(192, 168, 1, 1);
IPAddress subnet(255, 255, 255, 0);

unsigned int localPort = 4210;
```

SSID و رمز عبور Wi-Fi را با اطلاعات شبکه واقعی خود جایگزین کنید.

# UDP Sink در Python

UDP Sink در مسیر زیر قرار دارد:

```text
core/output/udp_sink.py
```

این بخش کدهای فرمان را به ESP32 ارسال می‌کند و دارای یک **فیلتر پایداری (Stability Filter)** است.

فیلتر پایداری مانع می‌شود که یک فریم دارای نویز به‌تنهایی بلافاصله به یک فرمان ربات تبدیل شود.

به‌صورت مفهومی:

```text
کد تشخیص‌داده‌شده
     │
     ▼
آیا کد در فریم‌های متوالی یکسان است؟
     │
   خیر ─────────────► بازنشانی کاندید
     │
    بله
     ▼
آیا به stability_count رسیده است؟
     │
   خیر ─────────────► انتظار
     │
   بله
     ▼
ارسال فرمان UDP
```

پیکربندی پیش‌فرض نمایش‌داده‌شده در پروژه:

```python
UDPSink(
    ip="192.168.1.150",
    port=4210,
    categories=None,
    stability_count=2
)
```

مقدار `ip` باید با IP ثابت ESP32 یکسان باشد.

# اجرای کامل سیستم ربات

۱. ESP32 را روشن کنید.
۲. Serial Monitor نرم‌افزار Arduino IDE را روی **115200 baud** باز کنید.
۳. منتظر بمانید تا ESP32 به Wi-Fi متصل شود.
۴. آدرس IP آن را تأیید کنید.
۵. مطمئن شوید IP مربوط به `UDPSink` در Python با IP ثابت ESP32 یکسان است.
۶. برنامه Python را اجرا کنید:

```bash
python main.py
```

۷. دست خود را مقابل دوربین قرار دهید.
۸. یکی از حرکات پشتیبانی‌شده را انجام دهید.
۹. تشخیص‌دهنده حرکت یک `Command` ایجاد می‌کند.
۱۰. UDP Sink پایداری فرمان را بررسی می‌کند.
۱۱. کد عددی از طریق Wi-Fi ارسال می‌شود.
۱۲. ESP32 کد را دریافت کرده و L298N را کنترل می‌کند.
۱۳. موتورها حرکت مربوط به آن فرمان را اجرا می‌کنند.

# نکات عملکردی برای کامپیوترهای ضعیف

برای سیستم‌هایی که منابع CPU محدودی دارند:

* `camera.model_complexity: 0` را نگه دارید.
* اگر فقط به یک دست نیاز دارید، تنظیم زیر را قرار دهید:

```yaml
camera:
  max_num_hands: 1
```

* در صورت نیاز از رزولوشن پایین‌تر دوربین مانند `320x240` استفاده کنید.
* از دستور زیر استفاده کنید:

```bash
python main.py --no-window
```

تا مصرف CPU مربوط به رندر تصویر محلی کاهش پیدا کند.

* اگر حجم ترافیک شبکه یا لاگ زیاد است، `hand_rig.stream_rate_hz` و `two_hand_frame.stream_rate_hz` را کاهش دهید.

# محدودیت‌های شناخته‌شده

* اولین اجرا ممکن است برای دانلود `hand_landmarker.task` به اینترنت نیاز داشته باشد. پس از کش‌شدن مدل، برنامه می‌تواند به‌صورت آفلاین کار کند.
* تشخیص حرکت جلو/عقب تقریبی است، زیرا یک دوربین تکی اطلاعات عمق واقعی ارائه نمی‌دهد. سیستم از تغییر ظاهری اندازه دست به‌عنوان نشانه عمق استفاده می‌کند.
* آستانه‌های تشخیص مربوط به فاصله، زاویه و سرعت بر اساس مقادیر معمول تنظیم شده‌اند و ممکن است برای شرایط مختلف نور، زاویه دوربین و اندازه دست نیاز به تنظیم داشته باشند.
* چارچوب هندسی دو دست بر اساس مچ دست و پایه انگشت اشاره هر دست محاسبه می‌شود. نقطه مورد استفاده برای بخش بالایی هندسه را می‌توان از طریق `TOP_LANDMARK_INDEX` در `core/two_hand_geometry.py` تغییر داد.
* پیکربندی فعلی ربات، کنترل سرعت متغیر موتورها را از طریق PWM فراهم نمی‌کند.

# توسعه‌های آینده

موارد زیر می‌توانند در آینده به پروژه اضافه شوند:

* بهبود دقت حرکات از طریق تنظیم آستانه‌های اطمینان.
* بهبود عملکرد در شرایط نوری مختلف و اضافه‌کردن هموارسازی نقاط دست.
* افزودن کنترل سرعت متغیر ربات با استفاده از `ENA` / `ENB` و PWM.
* افزودن حسگرهای فاصله برای جلوگیری خودکار از برخورد.
* پشتیبانی از چند ربات به‌صورت هم‌زمان با استفاده از شناسه دستگاه در پیام‌های UDP.
* افزودن حرکات سفارشی بیشتر تک‌دستی و دودستی از طریق معماری افزونه.
* افزودن تله‌متری غنی‌تر ربات و ارتباط دوطرفه.
* ساخت مصرف‌کننده‌های بیشتر برای جریان دستورات WebSocket، مانند Unity یا ریگ سه‌بعدی دست/کاراکتر.

## خلاصه پروژه

این پروژه بینایی ماشین، تشخیص حرکات، استریم بی‌درنگ، قابلیت توسعه نرم‌افزاری و رباتیک نهفته را در یک زنجیره واحد ترکیب می‌کند:

```text
حرکت دست
     ↓
نقاط دست MediaPipe
     ↓
تشخیص‌دهنده حرکت
     ↓
رجیستری فرمان
     ↓
فیلتر پایداری
     ↓
┌──────────────┬──────────────┬──────────────┬──────────────┐
│   Console    │   JSON Log   │  WebSocket   │     UDP      │
└──────────────┴──────────────┴──────────────┴──────────────┘
                                              ↓
                                            ESP32
                                              ↓
                                            L298N
                                              ↓
                                        موتورهای ربات
```

نتیجه، یک پلتفرم ماژولار است که نه‌تنها برای کنترل ربات، بلکه به‌عنوان یک رابط عمومی و بی‌درنگ مبتنی بر حرکات دست برای رباتیک، بازی‌ها، شبیه‌سازی‌ها، سیستم‌های تعاملی و ریگ‌های سه‌بعدی دست و کاراکتر نیز قابل استفاده است.
